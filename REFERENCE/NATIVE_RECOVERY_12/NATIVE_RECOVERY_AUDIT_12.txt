NATIVE RECOVERY AUDIT 12
=======================

SCOPE
-----
This audit moves beyond metadata names: it links Assembly-CSharp MethodDef tokens to ARM64 native addresses in the supplied libil2cpp.so and includes the resulting disassembly. It is not a managed C# decompilation. Native assembly is preserved verbatim so later reviewers can verify the interpretation.

INPUT PAIR
----------
Base APK: /mnt/data/base.apk (contains assets/bin/Data/Managed/Metadata/global-metadata.dat)
Architecture split: /mnt/data/split_config.arm64_v8a.apk (contains lib/arm64-v8a/libil2cpp.so)
ELF SHA-256: 4eebd81e9a28b556faf0ccaa2b70e7402b137e9e669284c70eb1b0d24466ee9f
Metadata SHA-256: 8c254808d083face6b981a6b3a0ae0886730f7a766a79dc672c12b6eb4cc9afd
Metadata: v29; ELF: 64-bit little-endian AArch64. The two artifacts are structurally paired by the recovered metadata image names and codegen module names/counts. This is strong structural evidence, not cryptographic proof they came from the exact same build.

REGISTRATION RECOVERY
---------------------
- Located one candidate Il2CppCodeRegistration at VA 0x19d8248.
- Located 40 CodeGenModule records at pointer array VA 0x1ada620.
- All 40 module records have structurally readable method-pointer arrays (40/40).
- Assembly-CSharp.dll module record: VA 0x1a68300, method pointer count 389.
- Metadata reports 41,767 methods, 5,997 types and 40 images overall.
- Applied ELF relocations: 171,795 R_AARCH64_RELATIVE and 1,567 R_AARCH64_ABS64; 151 relocations of another type were skipped.

NATIVE METHOD BODY COVERAGE
---------------------------
- The Assembly-CSharp method range export contains 371 methods.
- All 371 exported ranges have a matching .eh_frame FDE boundary (as recorded by the extractor).
- Total covered native bytes: 67544.
- The module has 389 method-pointer slots; therefore 18 slots are not represented in this FDE-backed range export. These may be null/no-body/abstract/extern or otherwise unresolved by this export. Do not infer their exact reason without checking the slot-state table.
- 371 distinct method ranges are present in this export. The raw full and focused disassembly files are included.

GENERIC METHODS
---------------
A separate generic registration pass recovered 28,047 generic method pointers and 28,132 generic method table entries, with 34,734 method specifications. No invalid generic table indexes were observed. Resolutions are in GENERIC_TARGET_HITS.csv/json. Generic definitions and concrete runtime instantiations are not always one-to-one; the included report explains this limitation.

WHAT THIS DOES NOT YET PROVIDE
------------------------------
1. C# source reconstruction: disassembly is native ARM64, not original source. Some high-level semantics still need careful manual lifting.
2. Full managed type/field reconstruction: metadata type and field tables need their own structured export and cross-check.
3. Unity serialized hierarchy: APK contains level0..level3 and split sharedassets bundles, but UnityPy/AssetRipper/AssetStudio are not installed in this environment. Scene string extraction is not equivalent to hierarchy reconstruction.
4. Generic/runtime dispatch completeness: generic methods, virtual dispatch, delegates, reflection and invokers need separate analysis. Direct BL cross-references do not capture every indirect call.
5. Runtime behavior: static native code does not prove what happens after runtime patching, dynamic data loading or device-specific execution.

NEXT STEPS
----------
A. Decode metadata field/type definitions and produce a full managed class schema (fields, types, offsets, attributes, method signatures).
B. Lift the key ARM64 functions into annotated pseudocode, starting with GenerateLevels, EasyGamemode Save/Load, TileClicked, row/column checks, undo and pause/quit lifecycle. Keep every statement tagged as observed, inferred or unresolved.
C. Parse Unity serialized files (level0..3, sharedassets0..3) to reconstruct GameObject trees, MonoBehaviour references, prefab links, UI layout and UnityEvent targets.
D. Resolve indirect calls, generated coroutine state machines and generic instances.
E. Compare static reconstruction with screenshots/runtime traces if the user can provide a screen recording or extracted Unity project/AssetRipper output.

REPRODUCIBILITY
---------------
The extractor scripts and raw outputs are included beside this report. The native ELF and metadata are not duplicated in this folder because they already exist in the workspace reference APKs. Re-run scripts only with the matching original APK pair and verify hashes above first.
